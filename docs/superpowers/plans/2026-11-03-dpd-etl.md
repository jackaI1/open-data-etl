# DPD ETL implementation plan

**Goal:** Finish a public, reproducible PySpark pipeline for Health Canada's marketed drug products.
**Architecture:** Download and checksum the marketed bulk archive, read explicit UTF-8 CSV schemas, clean and deduplicate products, derive SCD2 status events, enforce quality gates, then write date partitions and DuckDB tables.
**Tech stack:** Python 3.12, Java 17, PySpark 3.5, DuckDB, pytest, Make, GitHub Actions.
**Spec:** User-provided Spark ETL task; existing README-only repository and `skills/etl` worktree. Full execution, push, PR, and merge are authorized.

## Global constraints

- Preserve original apps, records, workers, and browser tabs; stop only owned test resources.
- Work on `skills/etl`; public repository `jackaI1/open-data-etl`; never force-push main.
- No credentials, personal records, generated warehouses, or application data in Git.
- CI must run the pipeline on the small public-data fixture; live download uses normal quality thresholds.

## Review focus

- Missing extracted files despite an unchanged download must be repaired.
- Invalid dates and missing required values must fail before load.
- Same-day status events and duplicate current flags need deterministic ordering.
- A failed DuckDB load must roll back all tables in that load.
- Same-date reruns must replace one partition while preserving other snapshots.

## Tasks

1. Run the existing tests; add regression cases for the review focus and textual strengths; verify failures, fix their causes, then run the whole suite.
2. Add Make targets, fixture provenance, SQL insight queries, CI on pushes and pull requests, and a weekly live download workflow retaining reports/outputs as artifacts. Document setup, diagram, thresholds, SCD2 semantics, and measured insights.
3. Review the full branch, run lint, tests, fixture and live pipelines, record results, clean up owned Spark processes, commit and push, open a PR, and squash-merge only after CI passes.
